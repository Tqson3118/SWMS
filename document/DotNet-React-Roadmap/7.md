# Chặng 7: React và hoàn thiện ứng dụng

Thời lượng tham khảo: 4–5 tuần. Điều kiện vào: hoàn thành một trang JavaScript/TypeScript gọi API ở Chặng 6.

Mục tiêu là chuyển Sổ chi tiêu sang React + TypeScript, hiểu component/props/state/effect, kết nối API, test luồng chính và deploy có kiểm soát. Redux, Zustand, TanStack Query và Clean Architecture là bước sau; chỉ thêm khi app có vấn đề cụ thể cần giải quyết.

## Chuẩn bị

```text
npm create vite@latest expense-web -- --template react-ts
cd expense-web
npm install
npm run dev
```

Đọc package.json và src/main.tsx trước khi sửa. Chạy API ở terminal riêng bằng `dotnet run --urls http://localhost:5000`. Tạo file `.env.local` trong frontend:

```text
VITE_API_BASE_URL=http://localhost:5000
```

Vite đưa biến có prefix `VITE_` vào bundle; không đặt secret ở đó. `apiBase` trong code sẽ ghép thành `http://localhost:5000/api/expenses`. Vì frontend dev thường ở `http://localhost:5173`, API phải cho phép đúng origin này bằng CORS như ví dụ Chặng 5; nếu dùng Vite proxy thay vì CORS thì ghi rõ proxy và dùng URL tương đối. Không áp dụng cả hai cách một cách mơ hồ.

## Tuần 1: component, JSX và state

### Buổi 1: JSX và component

Component là hàm nhận props và trả UI. Props truyền từ cha xuống con, không được con mutate. React dùng key ổn định khi render list; không dùng index nếu thứ tự có thể đổi.

```tsx
type Expense = {
  id: number;
  categoryId: number;
  categoryName: string;
  amount: number;
  spentOn: string;
  note: string | null;
};

type CreateExpenseRequest = {
  categoryId: number;
  amount: number;
  spentOn: string;
  note: string | null;
};

type ExpenseRowProps = {
  item: Expense;
  onDelete: (id: number) => void;
};

function ExpenseRow({ item, onDelete }: ExpenseRowProps) {
  return (
    <li>
      {item.categoryName}: {item.amount}
      <button onClick={() => onDelete(item.id)}>Xóa</button>
    </li>
  );
}
```

Bài tập: tạo ExpenseForm, ExpenseList và Summary; truyền props và callback từ App. Render trạng thái rỗng. Đừng dùng document.getElementById để đổi text trong React.

### Buổi 2: useState, form và immutable update

```tsx
const [items, setItems] = useState<Expense[]>([]);
const [categoryId, setCategoryId] = useState("");

function addItem(item: Expense) {
  setItems(previous => [...previous, item]);
}
```

State là snapshot của lần render. Khi cập nhật dựa trên state cũ, dùng functional updater. Tạo array/object mới thay vì push rồi set cùng reference. Controlled input giữ value trong state và onChange cập nhật nó.

Bài tập: form có `categoryId`, amount, date và note; dùng select để chọn category, đổi `categoryId` từ string của input thành number trước khi tạo `CreateExpenseRequest`. Validation client cho lỗi hiển thị; không lưu password hoặc log toàn bộ form. Test submit hợp lệ, category rỗng, amount âm và bấm submit nhiều lần.

## Tuần 2: effect, fetch và trạng thái

### Buổi 3: useEffect đúng cách

useEffect dùng để đồng bộ với hệ thống bên ngoài như network, subscription, timer hoặc DOM API. Nó không phải nơi mặc định để tính derived data có thể tính trong render.

Trước khi dùng đoạn trích bên dưới, component cần có state và URL API. Expense được định nghĩa ở Buổi 1; useState cần được import từ React:

```tsx
type LoadStatus =
  | { kind: "idle" | "loading" | "ready" }
  | { kind: "error"; message: string };

const [items, setItems] = useState<Expense[]>([]);
const [status, setStatus] = useState<LoadStatus>({ kind: "idle" });
const apiBase = import.meta.env.VITE_API_BASE_URL ?? "";
```

Đây là đoạn trích logic tải dữ liệu, không phải toàn bộ component:

```tsx
useEffect(() => {
  const controller = new AbortController();

  async function load() {
    setStatus({ kind: "loading" });
    try {
      const response = await fetch(apiBase + "/api/expenses", {
        signal: controller.signal,
      });
      if (!response.ok) throw new Error("HTTP " + response.status);
      const data: unknown = await response.json();
      setItems(parseExpenses(data));
      setStatus({ kind: "ready" });
    } catch (error) {
      if (error instanceof DOMException && error.name === "AbortError") return;
      setStatus({ kind: "error", message: "Không tải được dữ liệu." });
    }
  }

  load();
  return () => controller.abort();
}, [apiBase]);
```

parseExpenses không phải API của React mà là helper của bạn: nó nhận unknown, kiểm tra dữ liệu có đúng mảng và đúng kiểu field hay không, rồi mới trả về Expense[]. Có thể tái sử dụng validator đã luyện ở Chặng 6; không thay nó bằng ép kiểu Expense[] cho dữ liệu chưa kiểm tra.

Dependency phải chứa reactive values dùng trong effect; lint rule giúp phát hiện thiếu dependency nhưng không hiểu ý định thay bạn. Cleanup chạy trước effect chạy lại và khi component unmount. Trong StrictMode development, React có thể chạy thêm một chu kỳ setup/cleanup để phát hiện effect không đối xứng; không coi đó là bằng chứng production gọi API hai lần.

Bài tập: tải danh sách khi component mount, hủy request khi rời trang, hiển thị loading/error/empty/ready. Thử đổi apiBase và quan sát cleanup.

#### Lát cắt POST dùng cùng contract

Đặt helper này trong cùng component hoặc module API. `apiBase`, `parseExpense` và `setItems` phải dùng đúng những phần đã định nghĩa ở trên:

```tsx
async function createExpense(input: CreateExpenseRequest): Promise<Expense> {
  const response = await fetch(`${apiBase}/api/expenses`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(input),
  });

  if (!response.ok) {
    const detail = await response.text();
    throw new Error(`API ${response.status}: ${detail}`);
  }

  const data: unknown = await response.json();
  return parseExpense(data);
}

async function handleCreate() {
  const created = await createExpense({
    categoryId: Number(categoryId),
    amount: 120000,
    spentOn: "2026-09-22",
    note: null,
  });

  setItems(previous => [created, ...previous]);
}
```

Đây là điểm nối giữa form React và `ExpensesController`: request dùng `categoryId`, response trả thêm `categoryName`. Không tự đổi response thành `category` ở frontend, vì như vậy sẽ tạo ra một contract thứ hai.

### Buổi 4: derived state và state machine nhỏ

Tổng chi là derived value:
```tsx
const total = items.reduce((sum, item) => sum + item.amount, 0);
```

Không cần lưu total riêng rồi đồng bộ bằng effect. Mô hình hóa status bằng union giúp không hiển thị dữ liệu cũ như thành công khi request lỗi. Bài tập: thêm nút retry, disable khi đang gửi, và cập nhật list sau POST.

## Tuần 3: router, state chia sẻ và API

### Buổi 5: route và layout

Cài package router:

```text
npm install react-router-dom
```

Ví dụ tối thiểu (giả sử `ExpensesPage`, `CategoriesPage` và `NotFoundPage` đã được tạo):

```tsx
import { NavLink, Route, Routes } from "react-router-dom";

function AppRoutes() {
  return (
    <>
      <nav>
        <NavLink to="/expenses">Khoản chi</NavLink>
        <NavLink to="/categories">Danh mục</NavLink>
      </nav>
      <Routes>
        <Route path="/expenses" element={<ExpensesPage />} />
        <Route path="/categories" element={<CategoriesPage />} />
        <Route path="*" element={<NotFoundPage />} />
      </Routes>
    </>
  );
}
```

Ở `main.tsx`, bọc app bằng `BrowserRouter`:

```tsx
import { createRoot } from "react-dom/client";
import { BrowserRouter } from "react-router-dom";

createRoot(document.getElementById("root")!).render(
  <BrowserRouter>
    <AppRoutes />
  </BrowserRouter>,
);
```

Route client không tự tạo nhiều HTML page; server hosting phải fallback về `index.html` khi refresh route.

Bài tập: trang chi tiêu và trang danh mục dùng layout chung. Xử lý URL không tồn tại. Chưa cần Context chỉ vì có hai trang.

### Buổi 6: state cục bộ, lifting và Context

Giữ state ở component thấp nhất dùng nó. Nếu form và summary cần chung items, nâng state lên cha chung. Context tránh truyền props qua nhiều lớp, nhưng mọi consumer phụ thuộc context có thể re-render khi value thay đổi; tách provider/value hoặc giữ state cục bộ khi phù hợp.

Bài tập: tạo ThemeContext nhỏ cho dark/light, không đưa mọi input/modal vào global state. Khi có auth, lưu user/status cần thiết và xử lý logout; quyết định token storage dựa trên mô hình bảo mật API, không copy một mẫu JWT mù quáng.

### Buổi 7: error boundary và thư viện

Error boundary bắt lỗi render ở subtree theo khả năng framework, không thay thế xử lý lỗi async trong event/effect. TanStack Query có thể giúp cache/invalidation khi fetching nhiều; Redux/Zustand chỉ thêm sau khi bạn mô tả được pain point. Không học tất cả cùng lúc.

## Tuần 4–5: hoàn thiện và triển khai

### Buổi 8: UX và kiểm thử

Bổ sung loading, empty, error, success, focus input, label, keyboard, thông báo dễ hiểu. Test API 201/400/401/404/500 và mạng lỗi. Test add/delete/refetch bằng browser devtools. Không log token, password hoặc toàn bộ request body nhạy cảm.

### Buổi 9: cấu hình build

```text
npm run build
npm run preview
```

VITE_API_BASE_URL dùng cho build frontend; đây không phải secret. appsettings.json của backend là cấu hình .NET, không tự trở thành environment variable của browser. Cấu hình từng môi trường theo hosting provider, ghi rõ origin trong CORS, và không commit file secret.

### Buổi 10: checklist sản phẩm

Sổ chi tiêu bản hoàn chỉnh có:

- React + TypeScript: form, danh sách, tổng, lọc, route, trạng thái loading/error/empty;
- ASP.NET Core API: CRUD, pagination/filter, validation, ProblemDetails, logging, test;
- SQL Server: FK, CHECK, query tổng theo tháng/danh mục, migration;
- README: cách chạy backend/frontend, biến cấu hình không nhạy cảm, dữ liệu mẫu, known limitations;
- deploy thử và kiểm tra lại API origin, HTTPS, refresh route, migration và lỗi production.

Checkpoint: bạn giải thích được một click đi qua event handler, state update, render/effect, request HTTP, API/EF/database và response quay lại UI.
