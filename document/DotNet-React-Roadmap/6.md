# Chặng 6: Nền tảng frontend với HTML, CSS, JavaScript và TypeScript

Thời lượng tham khảo: 3–4 tuần. Điều kiện vào: đã gọi được API ở Chặng 5.

Mục tiêu là hiểu trình duyệt trước khi dùng React. Bạn sẽ làm một trang sổ chi tiêu bằng HTML/CSS/JavaScript thuần, rồi chuyển kiểu dữ liệu sang TypeScript. Không cần học mọi API của browser.

## Chuẩn bị

Cài Node.js LTS từ [nodejs.org](https://nodejs.org/), kiểm tra node --version và npm --version. Tạo thư mục frontend và dùng một dev server; mở file bằng double-click có thể làm module/fetch lỗi do origin file. Browser chạy JavaScript; TypeScript cần được build/transpile thành JavaScript trước khi browser chạy.

Tạo index.html tối thiểu khớp với selector trong ví dụ:

```html
<!doctype html>
<html lang="vi">
  <body>
    <form id="expense-form">
      <label> Số tiền <input id="amount" name="amount" inputmode="decimal" /> </label>
      <button type="submit">Thêm</button>
    </form>
    <p id="message" role="status"></p>
    <script type="module" src="./app.js"></script>
  </body>
</html>
```

Đặt app.js cùng thư mục và chạy một server tĩnh, ví dụ npx serve . hoặc dùng Live Server. Nếu selector không tìm thấy phần tử, code phải báo lỗi hoặc return thay vì gọi addEventListener trên null.

## Tuần 1: HTML và CSS

### Buổi 1: Semantic HTML và form

Dùng header, main, section, form, label, input, button và table/list có ý nghĩa. Label có thể liên kết tường minh bằng cặp `for`/`id`, hoặc bọc trực tiếp input như ví dụ ở trên; hai cách đều hợp lệ. Form là nơi nhận category, amount, date, note.

Bài tập: dựng markup cho trang gồm form thêm khoản chi, vùng thông báo lỗi, bảng danh sách và tổng. Thử submit khi category rỗng và kiểm tra thao tác bằng bàn phím.

### Buổi 2: Box model, Flexbox, Grid và responsive

Content, padding, border và margin tạo nên box model. Flexbox phù hợp bố trí một chiều; Grid phù hợp bố trí hàng/cột. Dùng media query khi layout cần đổi theo chiều rộng, không coi 768px là luật chung.

Bài tập: bố trí form bằng Flexbox, bảng bằng vùng cuộn, dashboard bằng Grid; kiểm tra 320px, 768px và màn hình rộng. Không dùng position absolute cho layout chính.

## Tuần 2: JavaScript

### Buổi 3: biến, hàm và array/object

Mỗi callback mảng nhận phần tử hiện tại; reduce thêm accumulator và giá trị khởi đầu. Có thể viết vòng lặp trước để thấy cùng một phép tính:

```javascript
const itemsForLoop = [
  { category: "Điện", amount: 500000 },
  { category: "Ăn uống", amount: 120000 }
];
let loopTotal = 0;
for (const item of itemsForLoop) {
  loopTotal += item.amount;
}
```

```javascript
const expense = { category: "Điện", amount: 500000 };
const items = [expense, { category: "Ăn uống", amount: 120000 }];

const total = items.reduce((sum, item) => sum + item.amount, 0);
const largeItems = items.filter(item => item.amount >= 200000);
console.log(total, largeItems);
```

const không cấm thay đổi nội dung object bên trong; nó ngăn gán lại biến sang object khác. Dùng map để tạo mảng mới, filter để chọn, reduce để gộp. Khi dữ liệu trở thành React state, tránh mutate mảng cũ.

Bài tập: tạo mảng 5 khoản chi, tính tổng, lọc trên 1.000.000, map sang text hiển thị. Kiểm tra mảng rỗng và amount bằng 0.

### Buổi 4: DOM và form event

```javascript
const form = document.querySelector("#expense-form");
const message = document.querySelector("#message");

if (!(form instanceof HTMLFormElement) || !(message instanceof HTMLElement)) {
  throw new Error("Thiếu phần tử form/message trong index.html");
}

form.addEventListener("submit", event => {
  event.preventDefault();

  const rawAmount = String(new FormData(form).get("amount") ?? "").trim();
  const amount = Number(rawAmount);
  if (rawAmount === "" || !Number.isFinite(amount) || amount < 0) {
    message.textContent = "Số tiền không hợp lệ";
    return;
  }

  message.textContent = "Đã nhận";
});
```

querySelector có thể trả null, nên code thật cần kiểm tra element tồn tại hoặc khởi chạy sau khi DOM sẵn sàng. Dùng textContent cho text người dùng; innerHTML với dữ liệu chưa tin cậy có thể mở cửa cho XSS. Bài tập: render danh sách bằng createElement/textContent, xóa một dòng bằng id, và không reload khi submit.

### Buổi 5: module và localStorage

Tách file helper bằng export/import sau khi hiểu script module:
```javascript
// money.js
export function formatMoney(amount) {
  return new Intl.NumberFormat("vi-VN").format(amount) + " ₫";
}

// app.js
import { formatMoney } from "./money.js";
console.log(formatMoney(120000));
```

localStorage chỉ lưu string và có thể bị xóa hoặc thay đổi; JSON.parse có thể throw nếu dữ liệu hỏng. Bài tập: lưu mảng expense bằng JSON.stringify, đọc bằng JSON.parse trong try/catch, xử lý key không có và JSON hỏng. Không lưu token nhạy cảm chỉ vì localStorage tiện.

## Tuần 3: fetch và TypeScript

### Buổi 6: Promise, async/await và fetch

fetch trả về Promise<Response>; fetch chỉ reject cho lỗi mạng/abort hoặc URL không hợp lệ, không tự reject chỉ vì status 404/500. Đọc body một lần, ví dụ response.json(); không “parse JSON hai lần”.

```javascript
async function loadExpenses(url, signal) {
  const response = await fetch(url, { signal });
  if (!response.ok) throw new Error("HTTP " + response.status);
  return await response.json();
}

const API_BASE_URL = "http://localhost:5000";

loadExpenses(`${API_BASE_URL}/api/expenses`)
  .then(data => console.log(parseExpenses(data)))
  .catch(error => console.error(error.message));
```

Rejection còn có thể do AbortController, CORS hoặc URL sai. CORS do server/browser policy cần được cấu hình đúng, không sửa bằng cách tắt bảo mật browser. Bài tập: hiển thị loading, success, empty và error; thử 404 và hủy request.

### Buổi 7: TypeScript

TypeScript kiểm tra kiểu lúc build; type bị xóa khi output thành JavaScript, nên không thay validation runtime. Interface mô tả shape cho compiler, không tự kiểm tra JSON từ server.

```typescript
type Expense = {
  id: number;
  categoryId: number;
  categoryName: string;
  amount: number;
  spentOn: string;
  note: string | null;
};

type CreateExpenseRequest = {
  categoryId: number;
  amount: number;
  spentOn: string;
  note: string | null;
};

function total(items: Expense[]): number {
  return items.reduce((sum, item) => sum + item.amount, 0);
}

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null;
}

function parseExpenses(value: unknown): Expense[] {
  if (!Array.isArray(value)) throw new Error("API không trả về một mảng");

  return value.map((item, index) => {
    if (!isRecord(item)) throw new Error(`Dòng ${index} không phải object`);

    const note = item.note;
    if (
      typeof item.id !== "number" ||
      typeof item.categoryId !== "number" ||
      typeof item.categoryName !== "string" ||
      typeof item.amount !== "number" ||
      typeof item.spentOn !== "string" ||
      !(note === null || typeof note === "string")
    ) {
      throw new Error(`Dòng ${index} có shape không hợp lệ`);
    }

    return {
      id: item.id,
      categoryId: item.categoryId,
      categoryName: item.categoryName,
      amount: item.amount,
      spentOn: item.spentOn,
      note
    };
  });
}

function parseExpense(value: unknown): Expense {
  const items = parseExpenses([value]);
  if (items.length !== 1) throw new Error("API trả về không đúng một expense");
  return items[0]!;
}
```

Các ví dụ JavaScript trước đó dùng `category` là text tạm trong bộ nhớ. Khi nối API Chặng 5, phải chuyển sang `categoryId` để gửi và `categoryName` để hiển thị; không dùng type cũ cho response từ server.

Bài tập: tạo type cho request/response API, dùng union cho trạng thái loading/error/success, và viết hàm runtime kiểm tra amount là number trước khi dùng. Không ép kiểu as Expense cho dữ liệu chưa kiểm tra.

### Buổi 8: Trang sổ chi tiêu thuần JS/TS

Ghép HTML, CSS và fetch API Chặng 5: thêm khoản, tải danh sách, hiển thị tổng, báo lỗi và disable nút khi đang gửi. Chạy backend bằng `dotnet run --urls http://localhost:5000`, rồi dùng `API_BASE_URL` ở trên. Nếu trang frontend chạy ở `http://127.0.0.1:5500` hoặc origin khác, phải thêm đúng origin đó vào policy CORS của API; `localhost` và `127.0.0.1` không nên coi là cùng một origin khi cấu hình. Ghi một bảng test gồm 2xx, 400, 401, 404, 500, mạng lỗi, response rỗng và response JSON sai.
