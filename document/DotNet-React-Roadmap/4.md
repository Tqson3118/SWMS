# Chặng 4: Database và SQL Server

Thời lượng tham khảo: 2–3 tuần. Điều kiện vào: Chặng 3 và biết Expense gồm id, category, amount, date.

Mục tiêu là hiểu dữ liệu quan hệ trước khi dùng EF Core. Bạn sẽ thiết kế database cho app chi tiêu, chạy truy vấn an toàn, và biết khi nào cần transaction. Các câu lệnh dưới đây dùng SQL Server.

## Chuẩn bị

Trên Windows, có thể dùng SQL Server LocalDB với instance MSSQLLocalDB và SQL Server Management Studio. Kết nối trong SSMS bằng Server name (localdb)\\MSSQLLocalDB, Authentication là Windows Authentication. Kiểm tra:

```text
sqllocaldb info MSSQLLocalDB
```

Nếu instance chưa chạy, khởi động nó bằng công cụ LocalDB theo [tài liệu Microsoft](https://learn.microsoft.com/sql/database-engine/configure-windows/sql-server-express-localdb). [SSMS download](https://learn.microsoft.com/ssms/install/install) là công cụ xem bảng/query. Luôn làm bài trong database học tập, không chạy UPDATE/DELETE trên dữ liệu thật.

```sql
CREATE DATABASE ExpenseDb;
GO
USE ExpenseDb;
GO
```

## Tuần 1: Mô hình quan hệ và bảng

### Buổi 1: Từ yêu cầu đến bảng

App cần khoản chi và danh mục. Một category có nhiều expense, nên thiết kế:

- Categories: Id, Name.
- Expenses: Id, CategoryId, Amount, SpentOn, Note.
- CategoryId là foreign key tới Categories.Id.
- Amount dùng decimal với precision/scale phù hợp; không dùng float cho tiền chỉ vì nó là số.

Primary key định danh một dòng. Foreign key có thể tham chiếu primary key hoặc một key có unique constraint, không bắt buộc mọi hệ quản trị chỉ cho trỏ tới PK. Ràng buộc giúp database từ chối dữ liệu không hợp lệ.

Bài tập: vẽ quan hệ 1–n trên giấy, ghi 3 dòng mẫu mỗi bảng, và trả lời điều gì xảy ra khi xóa category đang được dùng. SQL Server dùng NO ACTION (gần với restrict) hoặc CASCADE; chọn một quy tắc có lý do và ghi rõ tác động.

### Buổi 2: DDL, dữ liệu mẫu và NULL

```sql
CREATE TABLE Categories
(
    Id int IDENTITY PRIMARY KEY,
    Name nvarchar(100) NOT NULL UNIQUE
);

CREATE TABLE Expenses
(
    Id int IDENTITY PRIMARY KEY,
    CategoryId int NOT NULL,
    Amount decimal(18, 2) NOT NULL CHECK (Amount >= 0),
    SpentOn date NOT NULL,
    Note nvarchar(500) NULL,
    CONSTRAINT FK_Expenses_Categories
        FOREIGN KEY (CategoryId) REFERENCES Categories(Id)
);

INSERT INTO Categories (Name)
VALUES (N'Điện'), (N'Ăn uống');

INSERT INTO Expenses (CategoryId, Amount, SpentOn, Note)
VALUES (1, 500000.00, '2026-09-01', NULL),
       (2, 120000.00, '2026-09-02', N'Bữa trưa');
```

Kết quả mong đợi là hai category và hai expense; dòng Điện có Note NULL, dòng Ăn uống có Note “Bữa trưa”. Nếu chạy lại INSERT, UNIQUE Name hoặc dữ liệu trùng có thể làm lệnh lỗi; đó là lý do script mẫu cần dữ liệu sạch hoặc seed idempotent trong ứng dụng.

NULL nghĩa là chưa có/không biết giá trị, khác chuỗi rỗng và khác số 0. Dùng IS NULL, không dùng = NULL. decimal(18,2) là ví dụ, không phải quy tắc cho mọi tiền tệ.

Bài tập: thêm category trùng, amount âm, CategoryId không tồn tại, rồi đọc lỗi constraint. Ghi lại ràng buộc nào bảo vệ bạn.

## Tuần 2: SELECT, JOIN và thống kê

### Buổi 3: Đọc và lọc

```sql
SELECT Id, CategoryId, Amount, SpentOn
FROM Expenses
WHERE Amount >= 100000
ORDER BY SpentOn DESC;
```

WHERE lọc dòng trước khi nhóm; ORDER BY sắp xếp kết quả. Logical query processing là mô hình giúp hiểu ý nghĩa câu lệnh, không mô tả chính xác engine vật lý sẽ chạy thế nào. Với SQL Server, phân trang dùng OFFSET/FETCH; LIMIT là cú pháp của hệ khác.

```sql
SELECT Id, Amount, SpentOn
FROM Expenses
ORDER BY Id
OFFSET 0 ROWS FETCH NEXT 10 ROWS ONLY;
```

Bài tập: viết SELECT kiểm tra đúng các dòng sẽ bị sửa trước khi viết UPDATE. Tránh SELECT * trong code ứng dụng vì schema và dữ liệu trả về có thể lớn hơn cần thiết.

### Buổi 4: JOIN và GROUP BY

```sql
SELECT e.Id, c.Name AS CategoryName, e.Amount, e.SpentOn
FROM Expenses AS e
INNER JOIN Categories AS c ON c.Id = e.CategoryId;

SELECT c.Id, c.Name,
       COALESCE(SUM(e.Amount), 0) AS TotalAmount
FROM Categories AS c
LEFT JOIN Expenses AS e ON e.CategoryId = c.Id
GROUP BY c.Id, c.Name;
```

INNER JOIN chỉ giữ dòng khớp; LEFT JOIN giữ tất cả dòng bên trái và điền NULL khi không có dòng bên phải. Với category chưa có expense, SUM(e.Amount) có thể là NULL; COALESCE(..., 0) biến kết quả đó thành 0 khi báo cáo cần hiển thị số không. GROUP BY có thể dùng không có aggregate trong một số câu hợp lệ; aggregate như SUM/COUNT là mục đích thường gặp chứ không phải điều kiện cú pháp bắt buộc. Cột non-aggregate trong SELECT thường phải nằm trong GROUP BY; nhóm theo cả Id và Name giúp kết quả không phụ thuộc riêng vào tên.

HAVING lọc sau nhóm:
```sql
SELECT c.Name, SUM(e.Amount) AS TotalAmount
FROM Categories AS c
JOIN Expenses AS e ON e.CategoryId = c.Id
GROUP BY c.Name
HAVING SUM(e.Amount) > 1000000;
```

Bài tập: tổng theo tháng; danh mục chưa có khoản chi vẫn phải hiện; tìm khoản lớn nhất. Kiểm tra kết quả bằng dữ liệu nhỏ có thể tính tay.

## Tuần 3: UPDATE, transaction và thiết kế

### Buổi 5: UPDATE/DELETE an toàn

```sql
SELECT Id, Amount
FROM Expenses
WHERE Id = 1;

UPDATE Expenses
SET Amount = 550000.00
WHERE Id = 1;
```

Trước UPDATE/DELETE, chạy SELECT với cùng WHERE và đếm dòng. Trong bài học có thể dùng transaction để hoàn tác. Stored procedure nhận parameter giúp tổ chức truy vấn, nhưng bản thân việc gọi stored procedure không tự động ngăn SQL injection; query parameterization ở ứng dụng vẫn quan trọng.

Bài tập: cập nhật note, xóa một dòng mẫu, và mô tả cách khôi phục nếu WHERE sai. Không chạy câu lệnh thiếu WHERE trên database có dữ liệu cần giữ.

### Buổi 6: Transaction

Transaction bảo đảm nhóm thao tác được commit hoặc rollback theo quyết định của code. Một exception không tự động rollback mọi transaction; code phải rollback hoặc dùng mẫu/transaction API phù hợp.

```sql
BEGIN TRANSACTION;

UPDATE Expenses
SET Amount = Amount + 1
WHERE Id = 1;

-- Kiểm tra trước khi quyết định:
SELECT Id, Amount FROM Expenses WHERE Id = 1;

ROLLBACK TRANSACTION;
```

Bài tập: chạy rollback rồi kiểm tra giá trị không đổi; sau đó commit một thay đổi có chủ ý. Viết giả mã cho “chuyển tiền” gồm trừ A, cộng B, commit; nếu bước thứ hai lỗi thì rollback.
